# Introduction
This is the beginning of your cumulative exercise experience.  The intent for this 
exercise is to build a small web application using modern software engineering practices.  This 
exercise is much less prescriptive by design.  Your future customers generally won't care how you 
solve problems, just that they get solved.  Part of the discipline of software engineering is 
recognizing that certain best practices have an up-front cost but pay dividends over time.

## Overall Process
An overview of the full process is below.  Over the next two days, you will implement each
step of the process.  The instruction file will give you hints, but we expect that you utilize
prior course material, online material, and your brain to solve problems.  Your instructor
can assist you as well if you run into a road block.  Lines that are marked with a `!` are important!  You will need to complete those to do later steps in the process.

### Day 1 - Morning 
1. !Build a small web app in python
2. !Add test cases to your web app
3. Format and lint your code
4. Add pre-commit checks locally and push your code

### Day 1 - Afternoon
5. !Create a GH Actions pipeline in a new branch
6. !Validate your pipeline with a pull request
7. Add a new feature -- branch, test cases, code, push, merge

### Day 2 - Morning
8. !Build a docker image in a new branch
9. Update your pipeline to build & push the image
10.  Merge your changes in

## Topics Covered
1. git branching
2. fastapi web server
3. formatting and linting
4. pre-commit checks
5. unit tests
6. github actions & CI pipelines
7. docker images and containers

## Structure
This exercise is broken down into three time periods and two "difficulty levels".  The time period 
difficulty level are present in the name of the markdown file which follows the format 
`{day}_{period}_difficulty}.md`.  The `basic` difficulty is designed for those who are still learning
the basics of these principles.  The `intermediate` difficulty is designed for those who are a little
more comfortable with certain topics.  **The `intermediate` files assume that you have already completed 
the `basic` file for that day/period.**  The `intermediate` files extend the process and topics above
with additional material.

## LLM Advice
As usual, we suggest that you carefully prompt any LLMs you use to give you tips and suggestions
instead of providing the full answers.  LLMs are deliberately trained to be useful but this can 
degrade learning.  This can take some tweaking and experimenting to figure out the right prompts.  
Once you have a good prompt, save it somewhere so you can reuse it.

## Conclusion
This is a good exercise to assess your comfort and experience levels across a variety of topics.  
As you go through the process, think carefully about your weak spots and take notes to study those 
weak spots later.  Thoroughly understanding these concepts will leave you with a good foundation for
further learning and application development.
